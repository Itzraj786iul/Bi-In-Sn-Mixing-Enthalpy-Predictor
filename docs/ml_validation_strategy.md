# ML Validation Strategy

This document defines how we will evaluate future machine-learning models **before any ML code is written**. It is based on the actual files in this repository and the overlap analysis in `reports/ml_overlap_analysis.csv` (generated by `scripts/analyze_ml_overlap.py`).

**Not started yet:** model training, feature engineering beyond composition (+ optional temperature), or hyperparameter tuning.

---

## 1. Why validation design matters

We have three kinds of \(\Delta_{\mathrm{mix}}H\) labels:

1. **Experimental** — 104 calorimetry measurements (`source = paper_experiment`).
2. **Synthetic from RKM** — Dataset A (7389) and Dataset B (15453).

If we train on synthetic data and test on experimental data **without controlling overlap**, the ML model can look excellent for a bad reason: synthetic training points sit almost on top of the experimental test points, and both labels ultimately trace back to the **same RKM polynomial** (Dataset A) or the same surface (Dataset B near the measured lines).

The experimental observations remain the **ultimate real reference**. RKM is a validated benchmark (MAE 57.13 J/mol, RMSE 73.49 J/mol, R² 0.9510 on all 104 points) but is not a substitute for calorimetry.

Our validation design must answer distinct scientific questions and report limitations honestly.

---

## 2. Our three types of data

| Data | Rows | Composition coverage | Target | Noise | Role in ML |
| --- | --- | --- | --- | --- | --- |
| Experimental | 104 | Three cross-section lines only; \(x_{\mathrm{In}}\) ≈ 0.095–0.907 | Measured \(\Delta_{\mathrm{mix}}H\) | Real measurement scatter (tabulated \(u\)) | **Ground truth for evaluation** |
| Dataset A | 7389 | Same three lines; \(x_{\mathrm{In}}\) grid 0.09–0.91 step 0.001; 3 temperatures | RKM + noise | Yes | Dense synthetic along measured paths |
| Dataset B | 15453 | Full triangle; step 0.01; 3 temperatures | RKM only | No | Dense synthetic over entire simplex |

**Temperature note:** RKM ignores temperature. The same composition gives the same RKM value at 767, 813, and 855 K. Temperature is still stored in the CSVs and can be tested later as an ML input feature.

**Region labels (synthetic files):**

- `experimental_anchor` — within ~0.012 composition distance of a Table III point
- `near_experimental_cross_section` — within ~0.03 of a measured line
- `unsampled_ternary_region` — elsewhere (mostly Dataset B interior)

## 3. Experimental-only validation

**Scientific question:** Can ML learn \(\Delta_{\mathrm{mix}}H\) from calorimetry alone, with only 104 points?

**Proposed method:** **5-fold cross-validation** with **fixed random seed 42**, using features \([x_{\mathrm{Bi}}, x_{\mathrm{In}}, x_{\mathrm{Sn}}]\) (and optionally temperature in a separate run).

**Why not a single 80/20 split?** 104 points is small; one arbitrary split would be unstable. K-fold uses every point as test data once.

**Structure in the experimental file:**

- **3 cross-sections** (Bi-rich, equiatomic, Sn-rich bath), each with **34–36** points total across three temperatures.
- **9 series** = cross-section × temperature (11–12 points each).

Neighbouring points on the **same cross-section** share the same Bi:Sn bath ratio and differ mainly in \(x_{\mathrm{In}}\). They are **not independent**. A random 5-fold split can put one drop in the test fold and its neighbour in the training fold. That makes ordinary K-fold **somewhat optimistic** for “generalization along a new composition path.”

**Recommendation:**

| Approach | Use? | Why |
| --- | --- | --- |
| Random 5-fold CV on 104 points | **Yes — secondary / baseline** | Standard small-data practice; easy to compare models. Report that neighbours on the same line may leak information between folds. |
| Grouped CV by **cross-section** (3-fold leave-one-section-out) | **Yes — primary defensible metric** | Test fold is an entire composition path the model never saw. Matches the paper’s experimental design. |
| Grouped CV by **series** (9 groups) | Optional report | Finer grouping (holds out one temperature on one line). Smaller test sets (~11–12 points); useful but noisier. |

**Primary experimental-only metric:** leave-one-cross-section-out (LOCSO) — see Section 7.

---

## 4. Synthetic-to-experimental validation

**Scientific question:** If we train on synthetic data, can ML predict **real** experimental \(\Delta_{\mathrm{mix}}H\)?

**Naive setup (NOT recommended as primary):**

- Train: all Dataset A (or B)
- Test: all 104 experimental points

**Problem:** Dataset A was built on the **same three lines** with a **0.001** \(x_{\mathrm{In}}\) grid. Overlap analysis shows:

| Metric | Dataset A (same section + same T) | Dataset B |
| --- | --- | --- |
| Min distance | 0.000 | 0.000 |
| Median distance | 0.00031 | 0.0053 |
| Max distance | 0.00062 | 0.0081 |
| All 104 within 0.001? | **Yes** | No (5 within 0.001) |
| All 104 within 0.01? | **Yes** | **Yes** |

Every experimental point has a Dataset A neighbour on the **same cross-section and same temperature** within **0.001** composition units (max **0.00062**). The synthetic grid step is 0.001 in \(x_{\mathrm{In}}\), so this overlap is **by design**, not accident.

**Defensible synthetic → experimental protocol:**

When testing on experimental cross-section **X**, training synthetic data must **exclude all synthetic points on section X** (all temperatures on that line). Train synthetic on the other two sections only; test on experimental section X.

This removes same-line grid overlap. It does **not** remove the fact that labels are still RKM-based — that is a separate limitation (Section 13).

Dataset B is less overlapping at fine scale (0.01 grid) but still has neighbours within 0.01 for all 104 experimental points. Prefer **cross-section exclusion** over arbitrary distance cutoffs.

---

## 5. Synthetic data overlap problem

```text
Experimental point (measured ΔmixH)
        ↕  composition distance ≈ 0.0003 (Dataset A, same line)
Synthetic point (RKM + noise)
```

If both are in train/test split incorrectly:

- ML sees nearly the same \((x_{\mathrm{Bi}}, x_{\mathrm{In}}, x_{\mathrm{Sn}})\) in training.
- Test label is experimental; train label is RKM (+ noise) at almost the same composition.
- ML may interpolate the **local RKM relationship**, not learn independent physics.

**Dataset A:** serious overlap concern for naive train/test splits.

**Dataset B:** moderate concern near the three lines (all exp points within 0.01 of some B grid point); much less concern in the interior, but interior points were **never measured** — you cannot validate there against experiment.

**We will not randomly delete synthetic rows to improve scores.** Exclusion rules must be documented and tied to the experimental design (cross-section holdout), not tuned post hoc.

---

## 6. Composition-distance analysis

**Definition (used in analysis):**

\[
d = \sqrt{(x_{\mathrm{Bi,exp}} - x_{\mathrm{Bi,syn}})^2 + (x_{\mathrm{In,exp}} - x_{\mathrm{In,syn}})^2 + (x_{\mathrm{Sn,exp}} - x_{\mathrm{Sn,syn}})^2}
\]

Because mole fractions sum to 1, this is Euclidean distance in composition space.

**Temperature:** handled separately. Nearest-neighbour search for overlap used composition only first; Dataset A nearest neighbours on the same section almost always share the **same temperature** as the experimental point because the grid is replicated at 767, 813, and 855 K separately.

**Key counts (from actual data):**

Dataset A, same cross-section + same temperature:

| Threshold | Experimental points with a neighbour ≤ threshold |
| --- | --- |
| ≤ 0.0005 | 92 / 104 |
| ≤ 0.001 | **104 / 104** |
| ≤ 0.012 (`ANCHOR_DISTANCE` in generator) | 104 / 104 |

Dataset B:

| Threshold | Count |
| --- | --- |
| ≤ 0.001 | 5 / 104 |
| ≤ 0.005 | 49 / 104 |
| ≤ 0.01 | **104 / 104** |

Full per-point table: `reports/ml_overlap_analysis.csv`.

**Options considered:**

| Option | Verdict |
| --- | --- |
| A. Leave overlap; report limitation | Honest for exploratory runs; **not primary metric** for synthetic-assisted training |
| B. Distance exclusion zone around test points | Possible but arbitrary threshold; **not recommended** unless cross-section holdout is insufficient |
| C. Leave-one-cross-section-out | **Recommended** — simple, tied to paper design |
| D. Use Dataset B only for interior | Valid for a **separate** question; not for validating against Table III on the three lines |

## 7. Cross-section holdout

**Groups (from experimental CSV):**

| Cross-section | Experimental points |
| --- | --- |
| `(Sn0.33Bi0.67)1-xInx` | 34 |
| `(Sn0.50Bi0.50)1-xInx` | 34 |
| `(Sn0.67Bi0.33)1-xInx` | 36 |

**Leave-one-cross-section-out (LOCSO):**

For each held-out section \(S\):

- **Test:** all experimental points on \(S\) (34 or 36 points).
- **Train (experimental-only experiment):** experimental points on the other two sections.
- **Train (synthetic-assisted experiment):** synthetic points **not** on section \(S\) (exclude that section from Dataset A and/or B).

Repeat for all three sections. Report MAE, RMSE, R² per fold and averaged.

**What this tests:** “Can the model generalize from known composition paths to a **different** composition path?”

This is more meaningful than random splitting because points along one line are strongly correlated.

**Practical?** Yes. Three folds, balanced test sizes, aligns with how the calorimeter sampled the triangle.

**Optional extension:** leave-one-**series**-out (9 folds, ~11–12 test points) tests generalization to a new temperature on a known line. Report if useful, but LOCSO is the main cross-section generalization test.

---

## 8. Temperature experiment

RKM does not use temperature. The paper reports nearly temperature-independent \(\Delta_{\mathrm{mix}}H\) between 767 and 855 K.

**Two feature sets to compare later (same CV splits):**

1. \([x_{\mathrm{Bi}}, x_{\mathrm{In}}, x_{\mathrm{Sn}}]\)
2. \([x_{\mathrm{Bi}}, x_{\mathrm{In}}, x_{\mathrm{Sn}}, T]\)

Use the **same fold assignments** for both so differences are due to features, not split luck.

**Interpretation:** If adding \(T\) does not help (likely, given RKM and the paper), that supports treating mixing enthalpy as composition-dominated in this window. If ML gains from \(T\) while RKM ignores it, report carefully — ML may be fitting noise or series structure, not new thermodynamics.

Validation design supports both; no temperature-only splits required initially.

---

## 9. RKM as a benchmark

Every ML evaluation on experimental points must report **RKM on the same test points** for fair comparison:

\[
\text{RKM prediction} = \texttt{rkm\_delta\_mix\_h}(x_{\mathrm{Bi}}, x_{\mathrm{In}}, x_{\mathrm{Sn}})
\]

Using existing `src/rkm_model.py` — **no re-fit**, no new parameters.

On all 104 points (reference):

- RKM MAE = **57.13 J/mol**
- RKM RMSE = **73.49 J/mol**
- RKM R² = **0.9510**

For each CV fold or LOCSO fold, compute RKM MAE/RMSE/R² on **that fold’s experimental test set** and compare to ML on the identical points.

**Reading results:**

- ML better than RKM on synthetic test data → likely copied RKM or local structure; **not sufficient**.
- ML better than RKM on **held-out experimental** cross-section → scientifically interesting (check sample size and uncertainty).
- ML worse than RKM on experiment → ML has not beaten the thermodynamic baseline.

## 10. Recommended final evaluation design

Keep four experiments. Same metrics everywhere: **MAE, RMSE, R²** on experimental \(\Delta_{\mathrm{mix}}H\) (J/mol), plus RKM benchmark on the same test points.

### Experiment 1 — Experimental-only (baseline)

- **Train/test:** LOCSO on 104 experimental points (primary).
- **Also report:** 5-fold random CV, seed 42 (secondary; note neighbour correlation).
- **Features:** composition; repeat with composition + temperature.
- **Question:** How well can ML fit real calorimetry with no synthetic help?

### Experiment 2 — Synthetic-only → experimental test

- **Train:** Dataset A, **excluding** held-out cross-section (LOCSO).
- **Test:** experimental points on held-out section only.
- **Optional variant:** train on Dataset B excluding compositions on held-out section (coarser grid; different label noise policy).
- **Question:** Can ML trained on RKM labels predict **real** measurements on a new line?

**Primary synthetic trainer for this:** Dataset A (same lines, dense). Apply section exclusion.

### Experiment 3 — Combined (experimental + synthetic)

- **Train:** experimental points from two sections + synthetic (Dataset A) from two sections — **never** include held-out section in either source.
- **Test:** experimental held-out section (LOCSO).
- **Question:** Does adding synthetic data improve prediction of real experiment on a new path?

Compare to Experiment 1 (same test folds) and RKM benchmark.

### Experiment 4 — Cross-section holdout (explicit)

Same as LOCSO above; listed separately because it is the **core generalization test** shared by Experiments 1–3.

```text
                    ┌─────────────────────────────────────┐
                    │  Ultimate reference: 104 experiment   │
                    └─────────────────────────────────────┘
                                      │
          ┌───────────────────────────┼───────────────────────────┐
          ▼                           ▼                           ▼
   Exp 1: exp only              Exp 2: syn only              Exp 3: exp + syn
   LOCSO + 5-fold CV            LOCSO, exclude syn           LOCSO, exclude syn
   on experiment                on test section              on test section
          │                           │                           │
          └───────────────────────────┴───────────────────────────┘
                                      │
                              Compare to RKM on
                              same experimental test points
```

**Not recommended as primary:**

- Random train/test on pooled experimental + synthetic rows.
- Training on Dataset A including the test cross-section.
- Reporting ML accuracy on Dataset B interior as “validation” (no experimental labels there).
- Single holdout without cross-section grouping.

---

## 11. What we will NOT do

- Train models in this step.
- Randomly delete synthetic points to inflate scores.
- Treat synthetic \(\Delta_{\mathrm{mix}}H\) as independent experimental evidence.
- Use `base_model_prediction_J_per_mol` as an input feature when the target is also RKM-derived (feature leakage).
- Build validation frameworks, registries, or pipeline managers.
- Re-generate datasets or change RKM parameters.
- Claim R² on synthetic-only tests equals “accuracy on the physical system.”

**Ultimate test set / reference:** the 104 experimental rows in `data/original_experimental_data.csv`, evaluated through **leave-one-cross-section-out** (and secondarily 5-fold CV for experimental-only baseline).

---

## Four validation questions (summary)

| ID | Question | How we will test it |
| --- | --- | --- |
| **A** | Can ML learn from 104 experiments only? | Exp 1: LOCSO + 5-fold CV on experiment |
| **B** | Can ML learn the RKM relationship? | Train/test on synthetic only (diagnostic; **not** substitute for experiment). Compare ML to RKM on synthetic holdout. |
| **C** | Can synthetic training predict **real** experiment? | Exp 2: LOCSO, synthetic train excluding test section → experimental test |
| **D** | Does adding experiment to synthetic help? | Exp 3: combined train → same LOCSO experimental test as Exp 1 |

Question **B** is useful to check implementation but **Question C** and **D** against held-out **experiment** are the scientifically important ones.
